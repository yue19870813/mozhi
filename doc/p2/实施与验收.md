# P2 Windows 适配实施与验收

日期：2026-09-21。状态：**适配代码与验证流水线已落地，Windows 真机验收待完成**。当前开发机为 macOS Apple Silicon，不能将交叉类型检查视为 Windows 运行或安装包验收。

## 已实现

- Windows 原生适配独立为 `crates/platform-windows`，便于在 macOS 上使用 MSVC target 检查 Win32 API 类型。
- Rust 内部原生路径与 IPC/索引/恢复记录/ZIP 使用的 `/` 逻辑路径分离；拒绝设备保留名、ADS、盘符相对路径、UNC 输入、大小写和 Unicode 冲突。绝对目录选择仍由原生选择器处理。
- 拒绝 Windows reparse points，包括目录联接和云占位文件；遍历不进入这些目录。建议使用普通本地目录，OneDrive 占位库暂不支持。
- `FindFirstChangeNotificationW` 监听目录子树，切库时停止线程并关闭句柄；前端按秒合并通知，编辑/输入法组合/操作期间延后刷新。保留 5 秒轮询及前台核对作为漏报恢复路径。
- CredUI 原生密码框 + Windows Credential Manager Generic Credential，按仓库 URL/用户名哈希隔离，只供当前 Windows 用户读取，取消不写入。Token 不经过前端；原生临时密码缓冲清零。
- 平台显示 Ctrl/⌘ 与对应凭据名称；编辑器保留纯 CRLF 文件换行，新增文件默认 LF，混合换行归一为 LF。
- NSIS 当前用户安装、中英文安装界面、WebView2 引导下载、Windows ICO；不要求管理员权限。离线首次安装需预装 WebView2。
- Windows CI 运行前后端测试、Clippy、格式检查、NSIS 构建、安装/重复安装/卸载冒烟及一万篇性能探针，上传未签名安装包和报告。重复安装用于检查覆盖流程，不能代替跨版本升级验收。

## 开发与打包

Windows 10/11 x64，安装 Visual Studio 2022 Build Tools（Desktop development with C++、Windows SDK）、Rust stable MSVC、Node.js 22.12+、WebView2 Evergreen Runtime。

```powershell
npm ci
npm run tauri -- dev
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
npm run build
npm test
npm run tauri -- build --bundles nsis
```

Tauri 自动合并 `tauri.windows.conf.json`。产物在 `target/release/bundle/nsis/*-setup.exe`。CI 工作流为 `.github/workflows/windows.yml`，安装脚本只在隔离 runner 上运行。所有共享 Git 同步测试（分叉、文本/二进制冲突、重启续办和历史恢复）都会在 Windows 上重新执行。

## 签名与升级

自动更新未启用；当前采用下载安装包、退出应用、覆盖安装的手动升级。保持 identifier、产品名和安装范围稳定；每次发布同步提升 Cargo workspace、Tauri 和 npm 版本。安装器不应修改用户选择的笔记库。升级前导出独立备份。

签名脚本为 `scripts/windows/sign.ps1`：读取保护 runner 当前用户证书库中的证书，以 `MOZHI_CERT_THUMBPRINT` 选择，执行 SHA-256 Authenticode 签名、RFC3161 时间戳并验证。runner 需将 Windows SDK 的 signtool 加入 PATH。证书私钥由发布环境导入，禁止进入仓库。PR 验证任务不读取签名材料。

受保护发布环境中生成本地临时 Tauri 配置（绝对路径用 JSON 正确转义），例如：

```json
{"bundle":{"windows":{"signCommand":"pwsh -File C:/release/mozhi/scripts/windows/sign.ps1 %1"}}}
```

然后执行 `npm run tauri -- build --bundles nsis --config C:/release/signing.json`，由打包器对应用和安装包调用签名命令。证书和正式发布环境尚未提供，真实签名、时间戳与安装信任链仍待验收。以后如启用自动更新，必须另行配置更新清单服务、更新签名公钥及受保护私钥，不以 Authenticode 替代更新签名。
