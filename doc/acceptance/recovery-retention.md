# 操作恢复副本保留策略

每个笔记库独立保存设置，默认保留 30 天、1 GiB、1,000 条。
在打开笔记库、完成移动/删除、保存保留设置后，于 Tauri 阻塞工作线程中执行检查；与恢复和文件操作共用笔记库锁。
先清理过期记录，再按创建时间由旧到新清理超额记录。容量按 record.json 和 backup.json 的实际文件字节数计算，而非原始 Markdown 大小。

最近 24 小时、未完成、损坏、缺失备份或包含异常路径的记录不删除。受保护记录可使条数及容量暂时超限，恢复记录页显示提示。
没有 createdAt 的旧记录首次扫描时补写当前时间，给予完整的新保留期。未来时间戳按保护记录处理。
自动保存草稿、当前笔记和 Git 历史不属于清理范围。恢复副本不会消耗原记录。

手动“清理过期记录”展示数量、预计释放空间和不可恢复提示。执行时只处理已确认的集合，重新核对时间、完成状态及记录指纹；不会扩大到预览之后新过期的记录。清理错误展示在恢复页，不把已完成的移动/删除改判为失败。

## 自动验证

- 前端类型检查、生产构建及 Vitest。
- Rust 工作区测试：过期规则、容量和条数、24 小时边界、未来时间、旧格式迁移、损坏副本保护、手动预览后状态变化、跨库设置隔离、恢复保留、实际移动/删除生成记录。
- Unix 符号链接测试：操作目录、记录目录、备份文件、策略文件均不允许通过链接删除外部数据。
- Clippy（warnings as errors）、rustfmt 与 diff whitespace 检查。

## 尚需原生界面验收

在测试笔记库中检查设置页深浅主题、保存设置、清理预览/取消/确认及跨库切换；Windows 链接与文件锁行为需在 Windows 环境验收。此次没有对用户实际恢复目录执行清理，也没有进行原生界面点击验收。
